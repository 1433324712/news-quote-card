# 从读视频到双语素材包的完整工作流

本文件描述从拿到一个链接到交付“3 张金句卡 + 1 段 6 秒双语字幕视频 + 双语简介”的全过程。`SKILL.md` 给出规则与命令，这里给出每个阶段的做法、判断点和产物。

## 交付标准

一套合格的素材包满足：

- 3 张 1080×1440 PNG：钩子、核心金句、结论，版式与既有设计逐像素同源（同一 `render_card.py`）。
- 1 段 1080×1440 MP4：画面与音轨时长都等于目标（默认 6.000 秒），保留原声，烧录中英字幕。
- 所有引号内的文字都能在转写稿中逐字找到，附源视频时间戳。
- 双语简介：中文段、英文段、8–12 个话题标签。
- 交付报告中写明速度、裁切参数、删减与修正、需用户决定的事项。

## 来源与任务模式

### A. 来源类型

- **本地成片**：用户给出文件，直接 `--video`。
- **直链 MP4**：如 `video.twimg.com/.../1280x720/xxx.mp4`，`extract.py` 用 curl 下载。
- **平台帖子链接**：X 帖子先用 X 工具读帖子全文与媒体变体，选最高码率 MP4 直链；其他平台交给 yt-dlp。

### B. 任务模式

#### 主题跟随模式

用户给出主题（“末日论是烟雾弹”），片段内容恰好支撑。标题按主题写，引语从片段里找最能支撑主题的原话。

#### 片段真实内容模式

帖子主题与片段不符，用户选择按片段实际内容制作。此时主题由转写稿决定，标题重新提炼，不得保留帖子里片段没讲的观点。

#### 指定原话模式

用户直接给出想用的句子。仍需在转写稿中逐字核对，找到时间戳；找不到时告知用户，不照抄用户版本上卡。

## 推荐目录

```text
/workspace/raw/<slug>/
  video.mp4            源视频
  audio.raw            16 kHz 单声道 float32
  transcript.txt       分句时间戳（start-end 文本）
  words.txt            逐词时间戳
  frames/              抽帧 f_<秒>.png
  contact.jpg          帧总览
  quotes.md            原话记录表（人工维护）
  check.png            质检拼图
/workspace/deliverables/<slug>/
  01_hook.png  02_quote.png  03_takeaway.png  04_video_6s.mp4
/tmp/                  回归测试与临时输出
```

`<slug>` 用人物或主题的拼音/英文短名，如 `jensen-doom`、`sunyuchen-ai`。

## 阶段 0：确认任务

常见的用户输入与默认理解：

- “处理这个视频，中英双语 3 图 + 1 个 6 秒视频，写 XX”：默认交付集，主题为 XX，进入主题跟随模式；若核对失败转为询问。
- “做成素材”“出一套图”：默认交付集，主题待转写后提炼，并在交付中说明选题理由。
- “只要视频”“只要 3 张图”：按用户要求缩小交付集，其余阶段照常执行。
- “用他说的 XX 那句”：指定原话模式，先核对再使用。

开始前还要确认输出目录不与已有任务冲突；目录已存在且有成品时，换一个 `<slug>` 或征得用户同意再覆盖。

确认来源、主题、交付集与输出目录。用户只给了链接和主题时，按默认交付集执行，不反复追问。记下用户对风格的额外要求（如“抖音风”“更短的标题”）。

## 阶段 1：环境诊断

诊断只报告状态，不擅自修改系统。常见结论与处理：

- `ModuleNotFoundError: faster_whisper`：说明用途后安装；系统 Python 受 PEP 668 保护时加 `--break-system-packages`，或改用虚拟环境。
- 找不到 Noto Sans CJK：先查 `/usr/share/fonts/opentype/noto/`；仍没有时安装 `fonts-noto-cjk`，不要换成其他字体凑合，否则与既有版式不一致。
- 首次加载 medium 模型需要下载约 1.5 GB，提前告知用户耗时。

- `python3 -c "import faster_whisper, PIL, numpy"` 确认依赖；缺失时用 `pip install --break-system-packages -r requirements.txt`。
- `ffmpeg -version`、`ffprobe -version` 可用。
- `fc-list | grep -i "Noto Sans CJK"` 能看到 Bold 与 Regular。
- 平台链接需要 `yt-dlp`；X 直链不需要。

## 阶段 2：获得来源并建立来源记录

来源记录建议直接写在 `quotes.md` 顶部：

```text
帖子：https://x.com/<user>/status/<id>
媒体：https://video.twimg.com/amplify_video/<id>/vid/avc1/1280x720/<hash>.mp4
时长：761.17 s　分辨率：1280×720
烧录字幕：有（底部，约 y≥600）　台标：左下“黄金时代”、右上节目名
帖子摘要：1. … 2. … 3. …
```

下载后先看 `contact.jpg`：确认画面是帖子说的人物和场景、是否多机位、是否有片头片尾或广告。片头较长时，后续抽帧和选句都跳过这一段。

运行 `extract.py`，记录：帖子链接、媒体直链、时长、分辨率、是否有烧录字幕与台标。X 工具返回的 `duration_ms` 与 `ffprobe` 时长应一致，不一致说明拿错了视频。

## 阶段 3：核对帖子与片段

核对时注意三类常见情况：

1. **完全对应**：帖子是对片段的准确摘要，直接进入选句。
2. **部分对应**：片段只覆盖帖子的一两个观点。只用有出处的观点做卡，缺失的观点在交付中说明“片段未涉及”，不要凑数。
3. **完全不对应**：帖子摘要来自完整版长访谈，片段讲的是别的话题。按停止规则报告，并附上片段内容的分段概括，例如“0–245 秒：公链与交易所竞争；245–761 秒：量子计算对 BTC 的威胁”，方便用户快速选择。报告模板：

> 帖子列出的 N 个观点在这段 X 秒的视频里都没有出现。片段实际内容：……（按时间段概括）。可选：① 提供含这些观点的片段或完整版链接；② 按片段真实内容制作，候选原话为……（附时间戳）。请选择。

small 模型的中文转写会把专有名词写错，核对观点时按语义判断，不要因为错字误判为“没提到”；拿不准的段落用 medium 复核后再下结论。

逐条比对帖子文案中的观点与转写稿：

| 帖子观点 | 片段是否出现 | 时间段 |
|---|---|---|
| 观点 1 | 是 / 否 | 12.0–18.5 |

全部或主要观点缺失时，停止并报告：片段实际讨论了什么（按时间段概括）、可选方案（换片段或完整版 / 按片段真实内容做）。用户选择后再进入下一阶段。

## 阶段 4：用文字稿选题选句

### 多人访谈：先标说话人

在转写稿旁标出“记者 / 受访者”。Whisper 不区分说话人，需结合语义和画面判断；不确定时抽帧看谁在说话。

### 候选句评分

为每条候选句按 0–2 分打分：

- **冲击力**：一句话能否独立成立、有冲突或判断。
- **主题相关**：是否支撑用户主题（或片段真实主题）。
- **可读长度**：中文 ≤ 30 字、英文 ≤ 2 行为佳。
- **画面可用**：该时间段是否有正脸近景。
- **转写可信**：复核后措辞是否确定。

案例二的评分示例：“市场并没有 pricing Q-Day”冲击力 2、主题 2、长度 2、画面 2、可信 2，定为核心金句；“绝大多数行业的人低估了这件事情对 BTC 所带来的冲击”约 7 秒，冲击力 2、长度 1（需加速），定为视频句。

总分最高的一句给视频或核心金句卡；钩子卡优先选能引出冲突的句子或记者提问；结论卡选能落地的句子。

### 复核

复核示例（中文原声）：

```python
import numpy as np
from faster_whisper import WhisperModel
a = np.fromfile('audio.raw', dtype=np.float32)
m = WhisperModel('medium', compute_type='int8')
s0, s1 = 264, 300
segs, _ = m.transcribe(a[s0*16000:s1*16000], language='zh',
                       word_timestamps=True, initial_prompt='比特币 BTC 量子 Q-Day')
for s in segs:
    print(f'{s.start+s0:.2f}-{s.end+s0:.2f} {s.text}')
```

切片的时间偏移 `s0` 要加回到每个时间戳上，否则后续换算会错位。

对入选时间段用 medium 模型重转写（中文必须做，英文建议做），可加 `initial_prompt` 提示专有名词。复核结果写入 `quotes.md`。

### 与其他工具协作

- **X 工具**：读取帖子长文（`note_tweet`）、媒体 `variants` 与 `duration_ms`；帖子正文截断时以长文为准，避免漏掉帖子列出的后几条观点。
- **视频理解或内容分析工具**：可用于快速概括长片段的分段主题，但输出只能作为索引，最终引语仍以 Whisper 转写为准。
- **写作工具**：撰写简介和备选标题；交给它的引语必须来自 `quotes.md`，并要求它不得改写引号内文字。
- **图像生成工具**：本流程不使用生成图像替代真实视频帧；卡片主图必须是源视频的真实画面。

上游已经下载或转写过的素材直接复用，不重复下载、不重复整段转写。

## 阶段 5：把时间点校准成可用画面

抽帧命令示例：

```bash
for t in 270 276 284; do
  ffmpeg -v error -y -ss $t -i video.mp4 -frames:v 1 frames/k$t.png
done
```

把候选帧用 `xstack` 拼成 2×2 网格一起看，比逐张打开更快。选帧时同时观察烧录字幕的位置，为下一阶段的裁切做准备。若候选帧都在说话的中途、嘴型夸张，可前后移动 0.3–0.5 秒。

- 在每句时间段内每 1–2 秒抽一帧，挑正脸、眼睛睁开、表情有张力的一帧。
- 同一套卡的三张主图尽量来自不同时间点，避免三张一样。
- 远景双人画面只适合作为记者提问卡，或在交付中说明。

## 阶段 6：校准裁切区域

720p 源的经验值：字幕带上沿约在 y=595–610。`1003:564:40:0` 保留顶部 564 行、左右各裁 40/237 像素，比例 16:9；`1067:600:0:0` 保留更多画面但离字幕带更近。裁切后把一帧按 1080×608 放大检查，确认看不到任何字幕笔画残留。台标在裁切框内且不挡人物时可保留，并在交付中注明来源节目。

看原视频是否有烧录字幕：

- 无：不传 `--crop`。
- 有：抽 2–4 帧找字幕带上沿，取一个 16:9 裁切框覆盖人物、避开字幕，卡片与视频用同一参数。

## 阶段 7：确定视频起止与字幕切分

计算示例（案例二）：起 287.0、止 294.0，时长 7.0 秒，目标 6 秒，速度 = 7.0 / 6 = 1.1667。第一段到“行业的人”结束于源时间约 289.9，输出时间 (289.9 − 287.0) / 1.1667 ≈ 2.5；第二段到“这件事情”结束于约 291.6，输出时间 ≈ 3.95；第三段延续到结尾。

若句子短于目标时长，不使用 `--fit`，可把 `--start` 前移或 `--end` 后移，用前后的自然停顿补足；不要放慢原声。

- 从 `words.txt` 取起止，计算速度；速度 > 1.25 时考虑换句或截取半句。
- 字幕 3 段为宜，按语义断开，切点换算为输出时间。
- 中英两侧同一段表达同一部分意思。

## 阶段 8：渲染

渲染顺序建议：先渲核心金句卡，确认裁切、字号和断行没有问题，再渲钩子卡与结论卡，最后渲视频。这样一旦裁切框或断行需要调整，只返工一张。每张卡渲染后立即打开查看，而不是三张全部渲完再看。

### 金句卡

完整示例（案例二钩子卡）：

```bash
python3 "<SKILL_DIR>/scripts/render_card.py" --crop 1003:564:40:0 \
  --frame /workspace/raw/sunyuchen/k276.png \
  --tag '孙宇晨 × 金明 专访 | JUSTIN SUN' \
  --headline 'AI+量子\n盯上了比特币' --headline_en 'AI + quantum vs. Bitcoin' \
  --quote '“我觉得我相反是有点更看空…\n就是因为AI这个算法以及Q-Day的这个问题”' \
  --quote_en '"If anything, I'"'"'m a bit more bearish…\nbecause of AI algorithms and the Q-Day problem."' \
  --out /workspace/deliverables/sunyuchen-ai/01_hook.png
```

shell 中英文引语含撇号时，用 `'"'"'` 转义或改用双引号包裹参数。

逐张运行 `render_card.py`，标签、标题、引语按 `SKILL.md` 的写法；核心金句卡用 `--frame-y 420`。

### 视频

完整示例（案例二）：

```bash
python3 "<SKILL_DIR>/scripts/make_video.py" --crop 1003:564:40:0 \

  --title '孙宇晨：行业低估了Q-Day' --title_en 'Justin Sun: the industry underestimates Q-Day' \
  --subs '2.5|“我觉得绝大多数行业的人|"I think most people in the industry' \
  --subs '3.95|低估了这件事情|underestimate this' \

  --out /workspace/deliverables/sunyuchen-ai/04_video_6s.mp4
```

运行 `make_video.py --fit`，记录打印出的速度。

## 阶段 9：逐项质检

### 视觉检查

把 3 张卡与视频 3 帧拼成 `check.png` 先看整体，再逐张看原图：字体、颜色、顺序与默认版式一致；文字不贴边；原字幕不可见；主体完整。

### 技术检查

```bash
ffprobe -v error -show_entries stream=codec_type,width,height,duration -of compact 04_video_6s.mp4
for t in 1 3 5.5; do ffmpeg -v error -y -ss $t -i 04_video_6s.mp4 -frames:v 1 -vf scale=360:-1 /tmp/s$t.png; done
python3 -c "from PIL import Image;print(Image.open('01_hook.png').size)"
```

`ffprobe` 看分辨率与时长；确认音轨存在；PNG 尺寸 1080×1440。

### 语义检查

把 `quotes.md` 与成品逐项对读，确认以下几点再交付：

- 每条引语对照 `quotes.md`，含标点和省略号；
- 中英意思一致；标题判断可由引语推出；简介引号内文字与卡片一致。

## 阶段 10：有界返工

| 症状 | 只改 | 不要改 |
|---|---|---|
| 引语一行太长贴边 | 断行位置或换更短的原话 | 字号、版式 |
| 主图闭眼或模糊 | 帧时间 ±0.3–1.5 秒 | 裁切框 |
| 底部露出原字幕笔画 | 裁切框高度 `h`（保持 16:9） | 画面位置 `--frame-y` |
| 字幕早切或晚切 | 字幕切点（按 `words.txt` 重算） | 起止时间 |
| 句尾被截断 | `--end` 后移 0.1–0.2 秒，重算速度 | 目标时长 |
| 加速听感明显 | 换更短的句子或截半句 | 继续提高速度 |

一次只改一个变量：换帧、调切点、改断行、调裁切框。三轮仍不理想就报告限制。返工只覆盖本任务的输出目录，不动其他任务的成品。

## 阶段 11：交付

交付后保留可复现信息：每张卡的完整命令行（可写进 `quotes.md` 末尾），方便用户要求“只改一个标题”时快速重渲那一张，而不必重做整套。

按 `SKILL.md` 的交付结构汇报：文件路径、原话与时间戳、处理说明、简介、待决事项。素材与转写稿留在 `raw/` 目录供后续复用。
