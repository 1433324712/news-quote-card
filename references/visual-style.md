# 双语金句卡与字幕视频视觉规范

本规范描述既有设计，所有新素材必须与之完全一致。数值即 `render_card.py` 与 `make_video.py` 中的实现；需要改设计时先与用户确认，再同步修改脚本、本文件与回归基准。

## 核心判断

- 一套素材是“框架 + 证据”：大标题负责观点，引语与真实画面负责证据。
- 手机竖屏阅读优先：标题大、引语次之、英文最小但完整可读。
- 深色底、单一强调色：绿色 `#76B900` 只用于顶部细条与标签行，黄色 `#FFD600` 只用于中文引语与视频中文字幕。
- 真实画面不加滤镜、不加边框、不加贴纸，只做 16:9 裁切和等比缩放。
- 信息层级固定为四级：中文标题 > 中文引语 > 英文标题与英文引语 > 标签行。任何一张卡都不能打破这个顺序。
- 中文是主语言、英文是辅助：中文用更大字号和更亮颜色，英文保持完整句子而不是关键词，方便海外读者理解。
- 一套素材里只讲一个主题：三张卡与视频围绕同一条主线递进（问题 → 证据 → 结论），不在同一套里塞入片段中的其他话题。
- 留白是版式的一部分：顶部、画面上下与底部的深色区域不要用额外文字填满。

## 一套素材的视觉节奏

三张卡在同一版式下靠三个变量区分：标签、标题和主图。

| 卡 | 标签示例 | 标题语气 | 主图 |
|---|---|---|---|
| 01 钩子 | 人物 × 媒体 专访 \| NAME | 判断句、制造冲突 | 记者提问画面或受访者凝视镜头 |
| 02 核心金句 | 核心金句 \| KEY QUOTE | 固定“某某原话 / In his own words” | 受访者说出该句时的正脸 |
| 03 结论 | 结论 \| TAKEAWAY | 落点、等式或对比（“末日恐惧 = 挡箭牌”） | 带手势或表情变化的一帧 |

视频是第四个触点：标题与卡片的钩子或核心金句呼应，字幕用视频句的原话。标题不要与 01 卡完全重复，可换一个角度（“行业低估了 Q-Day”对应卡片的“AI+量子 盯上了比特币”）。

## 颜色与字体

| 元素 | 颜色 | 字体 |
|---|---|---|
| 背景 | `#0A0A0C` | — |
| 顶部细条 | `#76B900` | — |
| 标签行 | `#76B900` | Noto Sans CJK SC Bold 34 |
| 中文标题 | 白色 | Bold 78（视频标题 70） |
| 英文标题 | `#C8C8C8` | Regular 38 |
| 中文引语 | `#FFD600` | Bold 52（视频字幕 66） |
| 英文引语 | `#DCDCDC`（视频字幕为白色） | Regular 36（视频字幕 44） |

行高为字号的 1.3 倍；所有文字水平居中。

字体文件为 `/usr/share/fonts/opentype/noto/NotoSansCJK-Bold.ttc` 与 `NotoSansCJK-Regular.ttc`，ttc 内取 index=2（简体中文 SC 字形）。不同 index 的同一汉字字形不同（日文 JP、繁体 TC/HK），不要改。英文与数字同样使用这两个文件，保证中英混排时基线和字重统一。

颜色只出现在上表这些位置，不新增渐变、阴影、描边或半透明底板。深色底本身已保证白、黄文字在手机上足够对比；若某张主图下沿很亮，也不加描边，而是换帧。

## 金句卡布局（1080×1440）

| 区块 | 位置 |
|---|---|
| 顶部细条 | y=0–8 |
| 标签行 | 起点 y=70 |
| 中文标题 | 标签行结束后 +20 |
| 英文标题 | 中文标题结束后 +5 |
| 画面 | 1080×608，默认 y=(H−608)/2=416；核心金句卡 y=420 |
| 中文引语 | 画面底部 +50 |
| 英文引语 | 中文引语结束后 +10 |

2 行中文标题会推高英文标题，因此画面位置由 `--frame-y` 而不是标题高度决定；标题过长时可能压到画面上沿，必须看图验收。

## 字幕视频布局（1080×1440，与金句卡同为 3:4）

| 区块 | 位置 |
|---|---|
| 顶部细条 | y=0–8（与卡片相同） |
| 标签行 | 起点 y=70，绿色 Bold 34，与卡片相同：`人名 + 播客/采访 | ENGLISH NAME` |
| 中英标题 | 标签结束 +20 起中文 Bold 70，再 +5 英文 Regular 38 |
| 画面 | 1080×608，y=416（与卡片默认一致） |
| 字幕块 | 起点 y=1074（画面底 +50），中文 Bold 66 黄色，+10 后英文 Regular 44 白色 |

标题全程显示；字幕块按 `--subs` 切点依次切换，同一时刻只显示一段。

## 画面裁切

- 输入帧先按 `--crop w:h:x:y` 裁切，再等比缩放到 1080×608；不传时直接把整帧缩放到 1080×608，因此源视频本身应为 16:9。
- 裁切框必须是 16:9，否则会被非等比拉伸。常用：720p 无字幕源不裁；720p 底部有烧录字幕时用 `1003:564:40:0`（更安全）或 `1067:600:0:0`（保留更多画面）。
- 竖屏或 4:3 源要先裁出 16:9 区域；人物偏左或偏右时用 `x` 平移裁切窗口，让人物落在画面中线附近或三分线上。
- 一套素材中卡片与视频使用同一裁切参数；同一视频内不同机位如需不同裁切，在交付中说明。
- 低清源（低于 720p）放大到 1080 宽会变软，必须在交付中说明这不等于清晰度提升。

## 视频画面与编码

- 源片段先按速度 `setpts` 重定时间戳，再裁切、缩放到 1080×608、统一为 30 fps，叠加到深色模板 y=416 处。
- 标题模板与字幕层都是透明 PNG，由 `render_card.py` 的同一套字体与颜色绘制，保证与卡片一致。
- 编码固定 H.264（libx264，CRF 18，yuv420p）+ AAC 192k，并加 `+faststart`，适合抖音与 X 直接上传。
- 原声经 `atempo` 调速，保持音高；不加背景音乐、不做降噪或音量处理。
- 画面上不额外添加进度条、Logo、水印或动态贴纸；需要品牌标识时由用户另行要求。

## 手机缩略图可读性

成品在信息流里常以缩略图出现。把卡片缩到 360 宽查看：

- 中文标题仍能一眼读出；做不到就缩短标题，而不是放大字号。
- 黄色中文引语至少能读出主干词；英文可只要求能辨认。
- 主图里的人物表情可辨；若人物太小，换近景帧。


- 中文标题：每行 ≤ 8 字，最多 2 行。
- 英文标题：一行，≤ 45 字符。
- 卡片中文引语：每行 ≤ 16 字，最多 2 行。
- 卡片英文引语：每行 ≤ 50 字符，最多 2 行。
- 视频中文字幕：每段 ≤ 12 字；英文一行。

## 标点与引号

- 中文引语用全角 “ ” ，省略用 “…”；英文引语用半角 " " ，省略用 "…"。
- 跨两行的引语只在第一行开头和第二行结尾放引号。
- 记者提问以“记者：”开头，不加引号；英文用引号包住提问原文。
- 标签行中英文之间用 “ | ” 分隔，英文全大写（KEY QUOTE、TAKEAWAY、人名）。
- 标题里的等式或对比用半角空格包围符号，如“末日恐惧 = 挡箭牌”。

## 主画面选择

- 说话人正脸或 3/4 侧脸，眼睛睁开，嘴型自然。
- 头顶留白，下巴不贴画面下沿；裁切后人物不被切脸。
- 三张卡的主图来自不同时间点；钩子卡可以是记者画面。
- 避免双人远景、转场帧、模糊帧和片头字卡。

## 字幕节奏

- 6 秒视频切 3 段为宜，每段约 1.5–2.5 秒。
- 按意群切分，不在词中间切；引号只在第一段开头和最后一段结尾出现。
- 第一段从 0 秒开始显示，最后一段持续到结尾。

## 不要这样做

- 不要为了“更有冲击力”换成红色、渐变或霓虹配色；强调色只有绿与黄。
- 不要把引语放大到与标题同级，也不要把英文缩到 30 以下；层级靠字号区分，不靠颜色堆叠。
- 不要在画面上叠加原话气泡、箭头、圈注或表情包；画面只承担“真人真话”的证据作用。
- 不要用 AI 生成或修图的人物替代真实视频帧，也不要磨皮、美颜、调色。
- 不要为了填满版面把画面放大到超出 1080×608，或改成 4:3、1:1；版式依赖固定的画面高度。
- 不要在一套素材里混用不同版本的脚本或字体；改设计必须整套重出并更新回归基准。
- 不要把源视频的烧录字幕与我们的字幕同时保留，哪怕两者内容相同；双字幕会让手机画面显得拥挤且像搬运。


| 失败 | 修正 |
|---|---|
| 引语一行过长贴边 | 重新断行或换更短的原话 |
| 原字幕残留 | 调整 `--crop` 高度 |
| 画面变形 | 裁切框改为 16:9 |
| 三张主图雷同 | 换不同时间点的帧 |

## 最终视觉验收

先看整套缩略拼图（3 张卡 + 视频 3 帧），再看每个原尺寸文件。逐项确认：

- 颜色、字体、字号、区块顺序与本规范一致，没有新增装饰。
- 文字不贴边、不压画面、不重叠；中英文对应。
- 原视频字幕没有残留；画面没有变形；人物完整。
- 三张主图不雷同，与各自卡片语义相符。
- 视频标题全程可见；字幕依次切换、无空档；首尾帧都检查过。
- 与上一套交付物并排看时，版式肉眼无差别。

任一项不通过都按「常见失败及修正」只改对应变量，改完重新执行本节验收。
