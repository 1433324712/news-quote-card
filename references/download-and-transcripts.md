# 链接获取与逐字转写

本文件说明如何从 X 帖子或其他链接拿到可处理的视频，如何用 Whisper 得到带时间戳的转写稿，以及如何把转写稿变成可核对的原话。`extract.py` 封装了大部分步骤；这里解释每一步为什么这样做、出问题时怎么办。

## 先区分三种“文字”

| 文字 | 来源 | 能否当原话 |
|---|---|---|
| 帖子文案 | 发帖人写的摘要、标题、观点列表 | 不能；只用于确定主题和核对 |
| 烧录字幕 | 视频画面里已有的字幕（剪辑方添加） | 不能直接当原话；常有删改、错字、意译，只作参考 |
| 转写稿 | Whisper 对原声的逐字转写 | 可以，经复核后即为原话依据 |

三者冲突时以原声为准：转写稿与烧录字幕不一致的地方，回到音频试听确认。烧录字幕还会与我们的双语字幕重复，需要在渲染时用 `--crop` 裁掉。

## 依据与边界

- 只处理用户提供、可公开访问或用户有权处理的视频；不绕过登录、付费墙、地区限制或 DRM。
- X 的媒体文件由 `video.twimg.com` 提供多个码率变体；帖子接口会返回变体列表、时长和来源帖信息。
- faster-whisper 是 OpenAI Whisper 的 CTranslate2 实现，支持 `word_timestamps=True` 输出逐词时间，支持 `initial_prompt` 提示专有名词。
- 时间戳精度约 0.1–0.3 秒，足够切字幕，但视频起止要留少量余量。

## 环境检查

```bash
python3 -c "import faster_whisper, numpy, PIL; print('ok')"
ffmpeg -version | head -1
ffprobe -version | head -1
which yt-dlp || echo "yt-dlp 未安装（仅平台链接需要）"
```

检查结果的解读：

- 打印 `ok`：转写与渲染依赖齐全，可以继续。
- `ModuleNotFoundError`：缺哪个装哪个；只缺 `faster_whisper` 时，渲染脚本仍可用，可以先做已有转写稿的任务。
- FFmpeg 缺失：所有步骤都依赖它，必须先安装，不能用其他解码库替代。
- yt-dlp 缺失：只影响非直链的平台链接；X 帖子走直链即可不装。
- 没有 GPU 不影响使用：`int8` CPU 推理对几分钟的片段足够快，medium 复核 30 秒片段通常在半分钟内完成。

### 安装与更新原则

- 只在缺失时安装，先说明用途：`python3 -m pip install --break-system-packages -r "<SKILL_DIR>/requirements.txt"`。
- `yt-dlp` 按需安装，不预装；X 直链不需要它。
- 不升级或降级 PyAV、不修改系统 FFmpeg；遇到 PyAV 兼容问题，用 numpy 输入的方式绕开，而不是动环境。
- Whisper 模型首次使用会下载到本地缓存：small 约 500 MB、medium 约 1.5 GB。模型缓存可在任务之间复用。

## 获取顺序

### 1. 只读检查帖子与媒体

X 帖子先用 X 工具读取，不先下载：

- 读 `note_tweet.text`（长文全文）而不只是 `text`，避免漏掉观点列表的后几条。
- 展开 `attachments.media_keys`，读 `variants`、`duration_ms`。
- 有 `media_source_tweet_id` 时说明视频来自另一条帖子；记录原帖，必要时一并核对。
- 选 `content_type=video/mp4` 中码率最高的变体（通常 `1280x720`）；不要用 `.m3u8` 播放列表，也不要用 `preview_image_url` 当画面。

X 工具调用要点：

- 帖子查询时请求 `attachments.media_keys` 展开，以及媒体字段 `variants`、`duration_ms`、`media_key`；帖子字段请求 `note_tweet`、`attachments`。
- 返回中 `includes.media[].variants` 是变体列表：`bit_rate` 越高画质越好；`application/x-mpegURL` 是 HLS 播放列表，忽略。
- `duration_ms` 除以 1000 即秒数，用于之后与 `ffprobe` 对比。
- X 接口有调用额度限制，同一任务内读取一次即可，把结果写入来源记录，不反复查询。

记录到来源记录里的字段：帖子链接、作者、发帖文案（全文）、媒体直链、码率、时长、来源帖（如有）。这些信息之后会用于交付说明和简介写作，例如“完整版长达 3.5 小时”这类帖子信息，可帮助判断片段只是节选。

#### 从 X 搜索找素材

用户只给人物或主题、没给链接时，用 X 搜索近期带视频的帖子：查询词写人物全名并加 `has:videos -is:retweet`，`start_time` 用 UTC（北京时间当天 0 点 = 前一天 16:00Z），展开 `attachments.media_keys` 读 `duration_ms`。优先 30 秒–5 分钟、互动较多、帖子正文直接引用原话的帖子；排除 AI 生成的恶搞、拼接视频和纯解说。转载帖的视频常常来自更早的访谈，交付时说明“帖子发布于今天，访谈本身可能更早”。

### 2. 下载视频

```bash
python3 "<SKILL_DIR>/scripts/extract.py" \
  --url "https://video.twimg.com/amplify_video/<id>/vid/avc1/1280x720/<hash>.mp4" \
  --outdir /workspace/raw/<slug> --lang zh --model small
```

- URL 去掉查询参数后以 `.mp4` 结尾时，脚本用 `curl -sL` 直接下载；否则调用 `yt-dlp -f mp4/best`。
- 本地文件用 `--video <path>`，脚本不会复制它，只在 `--outdir` 写音频、转写与帧。
- 下载后用 `ffprobe` 核对时长；与帖子 `duration_ms` 相差超过 1 秒时，怀疑拿错变体或下载不完整。

下载完成后立即看一眼 `contact.jpg`，确认三件事：画面是帖子说的人物；有没有烧录字幕及其位置；有没有片头、广告或转场黑屏。三者都会影响后续选帧和裁切。

### 3. 解码音频

脚本用 FFmpeg 把音轨转为 16 kHz、单声道、float32 小端的裸数据 `audio.raw`：

```bash
ffmpeg -v error -y -i video.mp4 -ac 1 -ar 16000 -f f32le audio.raw
```

这样做有两个好处：避开部分 PyAV 版本 `metadata_errors` 参数导致的崩溃；复核时可以按秒切片 `a[s0*16000:s1*16000]`，不必重新解码。

### 4. 整段转写

整段转写用于“看全貌”和帖子核对：

- `transcript.txt`：每行 `start-end 文本`，分句级。
- `words.txt`：每行 `start-end 词`，逐词级。
- 英文原声 `--lang en`，中文原声 `--lang zh`；不传语言时 Whisper 会自动识别，但中英混杂的访谈容易判错，建议显式指定。
- 长视频（10 分钟以上）整段用 small 即可，速度快；中文专有名词错误留到复核阶段修正。

#### 中文转写的常见问题

- 专有名词音译错误：Q-Day → “QAIS”“QD”、BTC → “BDC”“比的比”、私钥 → “思要”、中本聪 → “中本村”。
- 繁简混用或同音字：以 medium 复核结果为准，统一为简体。
- 语气词与重复：“就是就是”“对吧”等可在上卡时删去，但删减要记入原话记录表。
- 英文词夹杂：pricing、ETF、action plan 等保留英文原样，不强行翻成中文。

#### 英文转写的常见问题

- 缩写与否定：don't / do、can't / can、won't / want 容易混淆，直接改变句意，必须试听。
- 口语省略：“I rather them focus” 实际可能是 “I'd rather them focus”；上卡时按听到的写，翻译按意思译，并在删减说明中注明。
- 数字与专名：“four or five CEOs”“33 years” 这类数字逐字保留；公司名、产品名按官方写法大小写（OpenAI、NVIDIA）。
- 重复起句：“What they're going, what they're transitioning from” 这类自我修正，只保留修正后的部分并用 “…” 标出。

### 试听确认

关键词不确定时，把该段音频单独导出试听，而不是反复猜测：

```bash
ffmpeg -v error -y -ss 89.5 -to 97.2 -i video.mp4 -vn -c:a aac /tmp/check.m4a
```

试听时重点确认：否定词、数字、专有名词、句首句尾是否完整。试听结论写入原话记录表。

### 5. 选段复核

对入选的时间段用 medium 模型重新转写，并提供专有名词提示：

```python
segs, _ = m.transcribe(a[s0*16000:s1*16000], language='zh',
                       word_timestamps=True,
                       initial_prompt='比特币 BTC 量子 Q-Day pricing')
```

- 切片前后各留 2–5 秒余量，避免句首句尾被切掉导致识别变差。
- 所有时间戳加回 `s0` 后再写入原话记录表。
- 复核结果与 small 结果差异较大时，以 medium 为准，并试听确认关键词。
- 英文原声同样建议对核心金句做一次复核，确认缩写与否定词（don't / do）。

### 时间戳的三种坐标

同一句话在流程中会出现在三种时间坐标里，换算错误是字幕错位的最常见原因：

| 坐标 | 含义 | 用在哪里 |
|---|---|---|
| 源时间 | 原视频中的秒数 | 原话记录表、`--start` / `--end`、抽帧 |
| 切片时间 | 复核切片内的秒数（从 0 开始） | Whisper 复核的原始输出 |
| 输出时间 | 成品视频中的秒数 | `--subs` 的切点 |

- 切片时间 + `s0` = 源时间。
- (源时间 − `--start`) / 速度 = 输出时间。
- 速度 = (`--end` − `--start`) / `--duration`（仅 `--fit` 时；否则为 1）。

写原话记录表时一律使用源时间；只有填 `--subs` 时才换算为输出时间，并把换算过程记在表的备注里，方便返工时核对。

### 文本整理与断句

Whisper 的分句不等于适合上卡的句子。整理时：

- 以语义为单位重新断句：一句完整的判断（主语 + 观点 + 原因）才适合做金句。
- 跨两个 Whisper 分句的同一句话可以合并，但必须连续、中间没有别人插话。
- 去掉明显的口误重复（“我觉得我觉得”），保留有意义的限定词（“我个人觉得”“可能”“至少有一种可能性”），限定词决定了观点的强弱，删掉就是夸大。
- 否定词、数量词、时间词必须逐字保留，并试听确认。
- 整理后的文本写回原话记录表的“原话”栏，并在“删减说明”栏写明整理了什么。

### 6. 抽帧

- 默认从第 2 秒起每 10 秒一帧，生成 `contact.jpg` 总览，用于判断机位、人物、字幕与台标。
- 用 `--frames 270,276,284` 在候选句附近精确抽帧，文件名为 `f_<秒>.png`。
- 精细选帧时可直接用 `ffmpeg -ss <t> -i video.mp4 -frames:v 1` 逐秒抽取。

## 转写可信度分级

为原话记录表中的每条原话标一个可信度，交付时一并报告：

| 等级 | 条件 | 能否上卡 |
|---|---|---|
| A | medium 复核与 small 一致，或经试听确认，关键词无疑问 | 可以 |
| B | medium 复核后措辞确定，个别语气词不确定 | 可以，删去不确定的语气词 |
| C | 关键词（否定、数字、专名）仍有疑问 | 不上卡；换句或请用户确认 |

核心金句卡和视频句必须是 A 级；钩子卡与结论卡至少 B 级。

## 片段内容概括

无论帖子与片段是否一致，都写一份按时间段的内容概括，每段一句话：

```text
0–245 s　公链与交易所：Solana、以太坊 DeFi 挖矿、Hyperliquid 与美股 Perps、监管决定 DEX/CEX 格局
245–761 s　量子与 BTC：AI 算法与 Q-Day 威胁、市场未定价、冷钱包隔离、个人从不关注转为密切关注
```

概括用于三件事：帖子核对时快速判断片段讲了什么；向用户报告不一致时给出依据；选题时决定一套素材讲哪一条主线。概括是解读，不加引号，不署名为原话。

## 交给翻译与写作之前

转写阶段结束时，应当产出一份“可交接”的材料，后续的翻译、标题和简介都只从这份材料出发：

1. 来源记录（帖子、媒体、时长、烧录字幕与台标情况）。
2. 帖子与片段的核对结果（逐条观点：出现 / 未出现 / 时间段）。
3. 原话记录表（用途、源时间、复核原话、删减说明）。
4. 片段内容的分段概括（每段一句话，标出时间范围）。
5. 候选帧清单（每句 1–3 帧的文件名）。

翻译时只看第 3 项；标题与简介可参考第 1、2、4 项，但引号内文字仍只能来自第 3 项。这份材料也是向用户报告“帖子与片段不一致”时的依据。

## 没有可用的转写

- 视频无音轨或只有音乐：无法得到原话，停止并告知用户。
- 原声嘈杂、多人同时说话：先试 medium；仍无法确定措辞的句子不使用。
- 原声为第三种语言：Whisper 可转写，但中英翻译都需要更谨慎；在交付中注明原语言。
- 烧录字幕清晰而原声难辨：烧录字幕只能作为参考，仍需尽量从原声确认；无法确认时向用户说明，由用户决定是否以字幕文字为准，并在简介中标注“据视频字幕”。

## 多个链接与批量任务

- 每个链接一个 `<slug>` 目录，互不覆盖；转写稿和原话记录表各自独立。
- 同一场访谈的多个片段可共享人物信息，但原话必须分别核对到各自片段的时间戳。
- 批量任务先完成所有片段的帖子核对，再统一选题，避免做到一半才发现某个片段与帖子不符。
- 模型只加载一次：在同一个 Python 进程里循环转写多个 `audio.raw`，比多次运行 `extract.py` 更快。

## 隐私与合规

- 素材只保存在 `/workspace/raw/` 与交付目录中，不上传到其他服务。
- 不在简介或卡片中加入片段外的个人信息（住址、家人、未经证实的传闻）。
- 转载他人采访时，在简介或交付说明中保留节目或媒体来源（如“CBS 专访”“仙道（金明）访谈”），由用户决定发布时是否注明出处。

## 登录与访问限制

- X 媒体直链通常可匿名下载；若返回 403 或空文件，先重新读取帖子获取新的变体链接。
- 需要登录才能观看的视频、私密帖子或付费内容，先向用户说明原因，不读取浏览器 Cookies、不让用户提供密码。
- 不使用第三方解析站点下载他人视频。

## 常见故障

### 下载的 MP4 只有几 KB

直链失效或被重定向到错误页。重新取变体链接；用 `ffprobe` 确认可读。

### `yt-dlp` 下载的不是 MP4

格式选择回退到了其他容器。保持 `-f mp4/best`，或下载后用 FFmpeg 转封装为 MP4 再用 `--video` 继续。

### 转写时间整体偏移

视频开头有静音或片头时，Whisper 可能把第一句时间标早。以 `words.txt` 与试听为准，必要时在原话记录表中手动修正。

### 转写结果出现大段重复

Whisper 在长静音或背景音乐处可能“幻听”重复上一句。这类片段不作为原话来源；对相邻时间段单独复核。

### 转写速度很慢

先确认使用的是 `compute_type='int8'`；长视频只用 small 整段，medium 只跑选段。

### 中文转写成了拼音或英文

未指定 `--lang zh` 时，Whisper 可能把中文识别为其他语言。显式传入语言后重新转写。

### 逐词时间戳缺失

只有在 `word_timestamps=True` 时才有逐词时间；`extract.py` 已开启。自写复核代码时别忘了加，否则无法精确切字幕。

### 同一句在 small 与 medium 中措辞不同

以 medium 为基础、试听为最终依据；两者都不可信时不使用这句，换一句同样能支撑主题的原话。
